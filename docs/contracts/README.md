## 공통 규칙

- **JSON 필드 이름은 camelCase**이고, 줄임말은 테이블정의서(6.1. 테이블정의서_StockShield.xlsx) 컬럼과 맞춥니다. 예: `tck_cd` → `tckCd`, `mbr_no` → `mbrNo`, `acnt_no` → `acntNo`, `ord_no` → `ordNo`.
- **시각은 ISO 8601, 한국 시간(+09:00)** 으로 씁니다. 예: `2026-11-10T10:00:01.123+09:00`
- **금액·가격은 원 단위 정수**, 수량은 정수입니다. 비율(등락률 등)만 소수(`number`)를 씁니다.
- 모든 Kafka 메시지와 Redis 값에는 **형식 버전 `v`** 를 넣습니다. 지금은 `1`입니다.
  - 필드를 **추가**하는 변경은 `v`를 올리지 않습니다. 받는 쪽은 모르는 필드를 무시해야 합니다.
  - 필드를 **삭제하거나 이름·의미를 바꾸는** 변경은 `v`를 올리고, 양쪽 담당자가 모두 리뷰한 PR로만 바꿉니다.
- 비밀값(내부 API 키, Redis 비밀번호, 한국투자증권 App Key)은 이 문서와 예시에 **실제 값을 넣지 않습니다.** 환경 변수로만 다룹니다.

## 이 문서를 바꾸는 방법

1. `feature/` 브랜치에서 문서를 고칩니다. 예시 JSON도 함께 고칩니다.
2. PR을 올리고, **바뀌는 형식을 쓰는 쪽 담당자를 리뷰어로 지정**합니다. 예: `order.log`를 바꾸면 조성우·윤제정.
3. 합쳐진 뒤에 코드를 바꿉니다. 코드가 먼저 바뀌어서 형식이 어긋나는 일이 없게 합니다.
